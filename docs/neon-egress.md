# Neon transfer / quota waste

**Status:** leftover payload/tick/retention work is on `main` (`5abe3e8`, after `48531d3`). OpenRouter (#3) stays parked.
**Scope:** `narulaskaran/agent-world` hosted production (Vercel Hobby + Neon Free/marketplace).
**World is parked.** Production still returns Neon **HTTP 402 data-transfer quota**, surfaced as `DATABASE_UNAVAILABLE` 503, until quota resets. These leftover cuts stop the observe path from making it worse after restore.
**Evidence mix:** code on `main` (verified), Vercel production runtime logs (2026-09-08), prior QA notes. `pg_stat_statements` was not available: Neon MCP is unauthenticated here and the compute is quota-blocked. Byte estimates are order-of-magnitude from query shapes, not a billing export.

## Changelog

- **Observe-path cut (`48531d3`):** read-only spectator `GET /api/state` (no presence write, due-job checks, or autonomy drain); ETag / If-None-Match; hidden-tab pause + 5xx backoff; memory/relationship caps; wallet DDL off `/state`.
- **Leftover cut (`5abe3e8`):**
  1. Slim `/api/state` board payload (id/pose/speech + map pick/render fields). Personality, memories, and relationships lazy-load from `GET /api/characters/:id`. ETag still applies to the slim snapshot.
  2. No `ensureSchema` on GET `/api/state`. World DDL stays on mutations and `/api/jobs/run` (once per process via `schemaReady`).
  3. Retention: delete completed `character_queue` rows; cap/prune artifacts (keep 80) and conversations (same keep/max-age as events). `listMemories` is by `character_id` only (export no longer dumps the table).
  4. Tick path: batch `FOR UPDATE SKIP LOCKED` claims (`LIMIT n`); `getRelationship` point-reads instead of full `listRelationships()` on QStash drains.
- OpenRouter (#3), sampled presence, and live Privy/onramp stay out of scope.
- **World tick cadence:** `AGENT_WORLD_TICK_INTERVAL_MIN` ∈ {10, 30, 60}
  (default 10; invalid values fail closed to 10). QStash can keep firing every
  10 minutes; `/api/jobs/run` skips autonomy drain until the interval elapses.
  Spectator poll stays ~4s + ETag and still does not advance the world.

---

Neon bills **public network transfer** as bytes **out of Postgres through the proxy** ([network transfer](https://neon.com/docs/introduction/network-transfer.md)). Free plan includes **5 GB / project / month**, then the compute suspends until the next cycle or an upgrade. The serverless HTTP driver (`neon()` in `packages/hosted/src/index.ts`) makes **one HTTP round-trip per SQL statement**, so call frequency and `SELECT *` width both count.

---

## Why we hit the quota

The hosted world is a **high-frequency, full-snapshot, write-on-read** loop against one Postgres project.

1. Every open tab calls `GET /api/state` **every 4 seconds**, plus on tab focus, with **no ETag / If-None-Match** and **no 5xx backoff**.
2. Each of those GETs **writes presence**, checks due jobs, and may **drain up to 8 autonomy jobs** (writes, SKIP LOCKED claims, event/memory/artifact inserts).
3. After that, the handler **re-reads the world**: all characters (`SELECT *`), **all active memories**, **all relationships**, 100 events, 80 artifacts.
4. N open spectators ≈ **N × 15 requests/minute**, each repeating (2)+(3). One always-on tab is already enough to exhaust a 5 GB month in a couple of days.
5. After Hermes (`16c87e6`), **every cold `ensureSchema()`** also walks **~45 extra wallet DDL statements** before serving `/state` or `/jobs/run`. Quota 402s were then retried per request until `80912fb` added a 60s in-memory block — still shorter than QStash retries, so parked cron **keeps poking Neon**.

This is the same pattern Neon’s docs flag: _high-frequency repeated queries of large result sets, no cache, serverless instance starts fresh_.

## UX poll cadence (recommended; do not implement in the dig)

Locked recommendations from QA. Documented here so a later change-PR can follow them without re-litigating product.

1. **Foreground:** keep ~4s feel. Prefer **delta / ETag** over a full snapshot. Client interpolation between ticks already exists (`world-scene.ts`).
2. **Background / hidden:** pause polling or drop to **≥30–60s**, or stop until focus. Today hidden tabs still `setInterval(4000)`; `visibilitychange` only **adds** a fetch on focus.
3. **On 5xx / `DATABASE_UNAVAILABLE`:** exponential backoff. Spectator poll must **not** drain jobs / autonomy side effects.
4. **Do not make foreground 30s** as the quota fix. Fix payload and writes first (items 1–3, 5–6).

## What multiplied after Hermes (`16c87e6`)

| Change                                                                         | Egress effect                                                                                                                                                                            |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WALLET_SCHEMA_STATEMENTS` (~45 DDL) invoked from every `ensureSchema()`       | Extra ~45 HTTP queries **per cold isolate**, including `/api/state` and `/api/jobs/run`. Direct cause of issue **#29** (opaque 500s), then quota retry storms until **#31** / `80912fb`. |
| `createProductionHandler` constructs `PaymentService` / `WalletFundingService` | **No extra SQL at construct time** (in-memory registry + fail-closed providers).                                                                                                         |
| New `/wallet/*` and `/admin/wallet/*` routes                                   | Not on the spectator poll. Irrelevant to the 5 GB burn unless something crawls them.                                                                                                     |
| `49f6771` best-effort wallet DDL                                               | `/state` survives wallet failure, but **still attempts** the statements first.                                                                                                           |
| `80912fb` 402 → 503 + 60s block                                                | Stops **dozens of wallet ALTERs per request** (the original storm). Does **not** stop QStash from probing every 10 minutes, and the 60s window is shorter than QStash’s ~2.5 min retry.  |

Hermes did **not** invent the 4s full snapshot; that predates it (`331ba25` hosted engine + polling). Hermes made cold starts and quota failures **more expensive** and helped push a busy project over the Free 5 GB line. The structural burn is still the poll loop.

## Stop the bleeding (while 503)

Ops first, then tiny server guards. **Do not ship poll UX in this dig.**

1. **Pause Upstash QStash** schedule `scd_7Bh9SNqWXfhxev2WiSYTGQ5CwNxb` (`HANDOFF.md`). Production evidence: it is the current 402 traffic.
2. **Do not leave production tabs open.** One `useWorld` interval is enough to re-exhaust quota after a reset.
3. **Disable or ignore Vercel daily cron** (`/api/jobs/run`) until Neon is restored (same handler path).
4. **Lengthen `dbBlockedUntil` on 402** (hours, not 60s) so QStash retries / leftover tabs cannot issue real SQL. Optional: skip `ensureSchema` entirely on `/jobs/run` after a quota error.
5. **Do not point `AGENT_WORLD_NEON_TEST_URL` at production** (issue #21). CI `neon.new` is a different project and does not explain prod 402s.
6. After Neon unblocks, **confirm with a single `/api/health`** before re-enabling QStash. Watch `data_transfer_bytes` on the Neon project/branch APIs.

## Measuring after a fix

When the compute is up:

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;

SELECT query, calls, rows AS total_rows, rows / calls AS avg_rows_per_call
FROM pg_stat_statements
WHERE calls > 0
ORDER BY rows DESC
LIMIT 15;
```

Expect today’s top `rows × calls` to be `SELECT * FROM memories`, `SELECT * FROM characters`, `SELECT * FROM relationships`, and `SELECT * FROM world_events … LIMIT 100`. After a poll fix, `calls` on those should drop by ~10–100× for the same spectator-minutes.
